# Self-Assessment_Agent_SOP.md

## 목적
Self-Assessment_Agent_SOP는 역량 평가 및 프로젝트 평가가 요청될 때 자동으로 호출되는 기준 문서이다. 시스템은 평가 요청 발생 시 본 SOP를 우선 참조하여 모든 평가 항목과 형식을 일관되게 유지한다.
언리얼 엔진 기반 프로젝트 및 개인 역량을 DevLog, Git Commit, PR 로그에 기초하여 체계적으로 평가하는 내부 표준 절차 문서. 포트폴리오, 역량 평가, 프로젝트 종합 리포트 생성을 위한 기반 프롬프트 사양.

---

## 트리거 규칙
- 사용자가 다음 유형의 요청을 수행할 때 본 SOP가 즉시 실행된다:
  - "역량 평가"
  - "프로젝트 평가"
  - "UE 개발자 평가"
  - "포트폴리오 분석"
  - "CTO/리드/PD/PM 관점 리뷰"
  - 자기진단(Self‑assessment) 요청

## 입력 데이터 범위
- DevLog 전체
- Git Commit 기록 및 PR 로그
- 태그/릴리즈 기록
- 기술 노트 및 설계 문서(존재 시)

데이터는 반드시 *객관적 기록* 기반으로 해석하며 추측/과장 금지.

---

## 산출물 종류
- 기간별 프로젝트 요약
- 전체 역량 평가 보고서
- 프로젝트 평가 보고서
- 멀티뷰(리더/CTO/PD/PM) 관점 분석
- 기술 선택 및 트레이드오프 분석
- 실패 사례 및 개선 전략
- 정량 지표 기반 증빙

---

## 평가 구성 항목

### 1) 기간별 프로젝트 요약
- 기간
- 목표
- 수행 작업
- 기술적 성과
- 해결 문제
- 로그/커밋 근거
- 다음 단계

### 2) 개인 역량 평가
- 핵심 요약
- 기술 심층 역량
- 구조화/시스템 설계 능력
- 디버깅 및 품질 관리 역량
- 자동화/툴링/DevOps 역량
- 문서화 및 공유
- 개선 목표

### 3) 조직 역할별 관점 평가
| 역할 | 판단 포인트 |
|---|---|
| 시니어 UE 개발자 | 기술 깊이, 문제 해결, 구조적 설계 |
| 클라이언트 리드 | 일정·품질 안정화, 팀 생산성 |
| CTO | 기술 전략, 비용/리스크 관점 |
| PD | 경험/기획 협업, UX 반응성 |
| PM | 일정, 리스크 관리, 커뮤니케이션 |

### 4) 다면 평가(360°)
- 동료 협업 근거
- 코드 리뷰/지식 공유 기록
- 작업 방식 및 행동 패턴

### 5) 실패 및 복기
- 주요 실패 사례
- 원인 분석
- 개선 접근
- 향후 방어 전략

### 6) 기술 선택 및 트레이드오프 분석
- 선택 배경
- 대안 비교
- 리스크 고려
- 최종 판단 구조

### 7) 정량 지표
- 커밋 밀도 및 패턴
- 기능 단위 완료 이력
- 리팩터링 비율
- 프로토타입 → 안정화 속도
- 성능/네트워크 개선 근거

## 평가 프레임워크 적용
- KPI / OKR / CFR
- 역량 모델 / BSC / MBO
- Output vs Outcome
- Competency Matrix (주니어 ~ 리드)

---

## UE 클라이언트 역량 기준
- GameInstance/GameMode/GameState/Subsystem 구조화 능력
- RPC/Replication/Seamless Travel/OSS
- UI/UMG/Slate/DPI/Streaming UI
- GC/Memory/Pooling/Asset/Profiling
- AI/BT/STT/TTS
- CI/CD/Build Scripts/Toolchain

---

## 프로젝트 평가 기준
- 목표 적합성 및 범위 관리
- 아키텍처 구조 안정성
- 완성도/성능/안정성
- UX 일관성 및 상호작용 흐름
- 운영/배포/빌드 파이프라인
- 재사용성 및 전체 구조 확장성
- 리스크 및 기술 부채 관리
- 사용자 가치 및 제품화 가능성

> 개인 성과와 프로젝트 품질을 분리 평가하고, 상호 연관성 분석 포함.
