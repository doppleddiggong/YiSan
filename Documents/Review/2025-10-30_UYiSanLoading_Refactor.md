# UYiSanLoading 리팩터링 리뷰 (2025-10-30 KST)

## 한 줄 요약
UYiSanLoading 서브시스템을 단계형 시퀀스로 재조직해 기존 함수명은 유지하면서 CPU 점유를 낮추고 진행률 계산을 안정화했다.

## 변경 전 주요 문제
- 텍스처 스트리밍 진행률 계산을 위해 `StreamAllResources`를 0.1초 주기로 호출하면서 메인/렌더 스레드를 지속적으로 깨워 CPU 점유율이 높았다.
- 네 가지 별도 로직(대기 건수, 강제 처리, 타임아웃, 정체 보정)을 중첩 적용해 코드 흐름이 복잡하고 진행률이 예측 불가능했다.
- 진행률 로그가 중복으로 출력되고, 함수/멤버 명명 규칙이 프로젝트 컨벤션과 달라 가독성이 떨어졌다.

## 적용한 개선 사항
1. **단계형 폴링 아키텍처**
   - 0.1초 간격 타이머는 유지하되 `WorldPartition → Texture → LevelInstance` 순으로 진행되는 단계형 시퀀스를 구성해 각 단계가 완료된 뒤에만 다음 로직을 실행하도록 했다.
   - 기존 퍼블릭 인터페이스를 유지하기 위해 `Poll_StreamingAndInstancesReady`, `Loading_Textures`, `Loading_LevelInstance` 등 함수명을 원본과 동일하게 복원했다.

2. **텍스처 스트리밍 진행률 정리**
   - 최초 대기 건수 대비 잔여 대기 건수 비율로 진행률을 계산하고, 엔진 기본 스트리밍 스레드가 자연스럽게 작업하도록 `StreamAllResources` 강제 호출을 제거했다.
   - 진행률 변화가 일정 수준 이상일 때만 5초 주기로 로그를 출력해 스팸을 방지했다.
   - 60초 타임아웃 조건은 유지하되, 완료 시점에 상태 변수를 명확히 리셋하도록 정리했다.

3. **상태 초기화 및 진행률 계산 정돈**
   - 단계 진입 시마다 필요한 변수를 리셋하는 `ResetLoadingState`와 `AdvanceToStage`를 추가해 진행률 계산이 안정적으로 초기화되도록 했다.
   - 10% 단위 브로드캐스트와 텍스처 진행 로그 스로틀링을 유지해 로그 스팸을 방지했다.

4. **Legacy 대비 시간 추적 로그 추가**
   - 각 단계 진입/완료 시 `[타이밍] (Legacy 비교)` 로그를 남겨 이전 로딩 파이프라인과 동일한 타임라인 구간을 KST 기준으로 기록한다.
   - 최종 완료 시 `WorldPartition`, `TextureStreaming`, `LevelInstance` 단계별 시작/종료/구간 소요 시간을 요약 출력해 개선 전후 로딩 시간을 정량적으로 비교할 수 있도록 했다.
   - 구 버전과 비교하려면 개선 적용 전 브랜치를 checkout 한 뒤 동일한 로깅 지표(`[타이밍]` 태그)를 캡처하고, 개선 버전 로그와 비교한다.

## 기대 효과 및 영향 범위
- 불필요한 스트리밍 강제 호출이 사라져 로딩 구간의 CPU 점유율이 안정화되며, 스트리밍 스레드가 과도하게 깨지지 않는다.
- 진행률 계산식이 단일 경로로 관리돼 후속 유지보수(가중치 변경, 타임아웃 조정)가 용이하다.
- UI 측에서는 기존 브로드캐스트 인터페이스를 유지하므로 추가 수정 없이 동작한다.

## Legacy vs 개선 버전 비교 절차 (가이드)
1. **Baseline 수집**: 개선 적용 전 커밋을 checkout 한 뒤 동일한 테스트 시나리오에서 로딩을 수행하고 `[타이밍] (Legacy 비교)` 로그를 수집한다.
2. **개선 버전 측정**: 본 커밋을 적용한 상태에서 동일 시나리오를 재실행해 `[타이밍] (Legacy 비교)` 로그와 요약을 획득한다.
3. **비교 지표**: 단계별 `단계 소요` 값과 최종 `총 소요 시간`을 비교해 CPU 점유율 및 체감 개선 폭을 평가한다.
4. **보고**: 차이는 `Documents/DevLog` 또는 별도 성능 리포트에 누적 기록하고, 추가 최적화 후보(Streaming Pool, DDC 사전 빌드 등)를 검토한다.

## 테스트 및 확인 사항
- 코드 변경은 C++ 빌드 대상이며, 테스트는 프로젝트 정책에 따라 수동 확인 단계에서 진행 예정이다.
- 로딩 구간 로그는 5초 주기로만 출력되며, 총 진행률은 10% 단위로 브로드캐스트된다.

## 후속 권장 사항
- 필요 시 `InitialTextureRequestCount`를 PersistentLevel 단위가 아닌 `StreamingManager` 전체로 캡처하도록 확장해 대형 맵 로딩 시 정확도를 높일 수 있다.
- Texture Streaming Pool 크기 조정 등 엔진 레벨 튜닝은 별도 작업으로 진행 권장.
