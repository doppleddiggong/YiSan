## 문제 개요

### 현상
- Daily Report가 생성되고 Discord에 알림이 전송됨
- Discord 링크 클릭 시 GitHub Pages에서 **404 Not Found** 에러 발생
- 사용자가 최신 DevLog 문서를 확인할 수 없는 상황

### 영향 범위
- 2025-11-08, 2025-11-09 Daily Report 문서 접근 불가
- GitHub Pages (https://doppleddiggong.github.io/YiSan/docs/) 최신 문서 미반영
- Discord 알림의 신뢰성 저하

### 기대 동작
1. Daily Report 자동 생성 → docs 브랜치에 커밋
2. HonKit 자동 빌드 → gh-pages 브랜치에 배포
3. GitHub Pages에서 최신 문서 즉시 확인 가능
4. Discord 링크 정상 작동

## 문제 발견 과정

### 1단계: 사용자 피드백 분석
**사용자 보고**:
> "daily report로 생성된 11-08.md 라는 리포트 문서가 있다고해. 그래서 디스코드 센더까지 잘 돌았는데, 정작 main쪽에는 그 문서가 없어서, 링크를 누르고 오면 못 보는 상황이야."

**초기 가설**:
- docs 브랜치에만 파일이 있고 main 브랜치에는 없어서 발생하는 문제로 추정

### 2단계: 브랜치 구조 확인
```bash
# docs 브랜치에 파일 존재 확인
git ls-tree remotes/origin/docs Documents/DevLog/Daily/ | grep "2025-11-0[89]"
# 결과: ✅ 2025-11-08.md, 2025-11-09.md 존재

# SUMMARY.md에도 포함 확인
git show remotes/origin/docs:Documents/SUMMARY.md | grep "2025-11-0[89]"
# 결과: ✅ 정상적으로 포함됨
```

### 3단계: GitHub Pages 배포 상태 확인
```bash
# gh-pages 브랜치 최근 배포 확인
git log remotes/origin/gh-pages --oneline --since="2025-11-08"
# 결과: ❌ 2025-11-08/09 이후 배포 없음

# gh-pages의 Daily 폴더 확인
git ls-tree remotes/origin/gh-pages -r --name-only | grep "DevLog/Daily"
# 결과: ❌ 최신 파일 없음 (2025-10-XX까지만 존재)
```

**결론**: docs 브랜치에는 파일이 있지만, gh-pages로 배포되지 않음

## 근본 원인 분석

### 문제의 핵심
**HonKit 워크플로우가 docs 브랜치 커밋 후 자동으로 실행되지 않음**

### 브랜치 구조 분석

#### 현재 설정
```
main 브랜치: 워크플로우 정의 관리
docs 브랜치: 문서 자동 생성 및 보관 (Actions 전용)
gh-pages 브랜치: HonKit 빌드 결과 배포
```

#### 워크플로우 실행 흐름
```
1. daily-report.yml (main 브랜치에서 실행)
   ↓
2. checkout with ref: docs (docs 브랜치로 전환)
   ↓
3. DevLog 파일 생성 (Documents/DevLog/Daily/)
   ↓
4. docs 브랜치에 커밋
   ↓
5. ❌ HonKit 실행 안됨 (트리거 없음)
   ↓
6. ❌ gh-pages 업데이트 안됨
```

### honkit.yml 트리거 설정 분석
```yaml
on:
  push:
    branches:
      - main
      - dopple
      - docs  # ← docs 브랜치 push 시 트리거 설정됨
    paths:
      - 'Documents/DevLog/**'
      - 'Documents/Planning/**'
```

**문제점**:
- daily-report는 main 브랜치에서 실행되어 docs 브랜치에 커밋함
- 하지만 **GitHub Actions는 Actions로 만든 커밋에 대해 push 이벤트를 트리거하지 않음** (무한 루프 방지)
- 결과적으로 honkit.yml이 실행되지 않음

### GitHub Actions 제약 사항
공식 문서에 따르면:
> "An action in a workflow run can't trigger a new workflow run. For example, if an action pushes code using the repository's GITHUB_TOKEN, a new workflow will not run even when the repository contains a workflow configured to run when push events occur."

**결론**: push 이벤트로는 트리거할 수 없음. 다른 메커니즘 필요.

## 해결 방법

### 선택한 솔루션: `repository_dispatch` 이벤트

#### repository_dispatch란?
- GitHub Actions에서 제공하는 수동 워크플로우 트리거 메커니즘
- API 호출 또는 다른 워크플로우에서 이벤트를 발생시켜 워크플로우 실행
- Actions 간 체이닝(chaining)에 사용

#### 구현 전략
```
daily-report.yml (생성자)
  ↓ repository_dispatch 발생
  ↓ event-type: honkit-build
  ↓
honkit.yml (수신자)
  ↓ repository_dispatch 트리거
  ↓ types: [honkit-build]
  ↓
  실행
```

#### 장점
1. ✅ Actions 제약 우회 (push 이벤트 불필요)
2. ✅ 명시적인 워크플로우 체이닝
3. ✅ 이벤트 타입으로 트리거 소스 구분 가능
4. ✅ payload로 추가 정보 전달 가능

---

## 구현 과정

### 1단계: honkit.yml 트리거 추가

**파일**: `.github/workflows/honkit.yml`

**변경 내용**:
```yaml
on:
  # 기존 push 트리거 유지
  push:
    branches:
      - main
      - dopple
      - docs
    paths:
      - 'Documents/DevLog/**'
      - 'Documents/Planning/**'
      - 'Documents/*.md'
      - 'Documents/book.json'
      - '.github/scripts/generate_summary.py'

  # ✨ 추가: repository_dispatch 트리거
  repository_dispatch:
    types: [honkit-build]

  # 수동 실행 가능
  workflow_dispatch:
```

**설명**:
- `repository_dispatch`: 외부에서 이벤트를 받아 실행
- `types: [honkit-build]`: 'honkit-build' 타입의 이벤트만 수신

### 2단계: daily-report.yml 트리거 추가

**파일**: `.github/workflows/daily-report.yml`

**변경 내용**:
```yaml
      - name: Commit and Push
        run: |
          # ... (기존 커밋 로직)

      # ✨ 추가: HonKit 빌드 트리거
      - name: Trigger HonKit Build
        uses: peter-evans/repository-dispatch@v2
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          event-type: honkit-build
          client-payload: '{"ref": "docs", "trigger": "daily-report"}'

      - name: Summary
        run: |
          # ... (기존 Summary)
```

**사용한 액션**:
- `peter-evans/repository-dispatch@v2`: 안정적인 repository_dispatch 구현
- `token`: GitHub API 인증
- `event-type`: 'honkit-build' 이벤트 발생
- `client-payload`: 트리거 소스 정보 전달 (추적용)

### 3단계: weekly-report.yml 트리거 추가

**파일**: `.github/workflows/weekly-report.yml`

**변경 내용**: daily-report.yml과 동일
```yaml
      - name: Trigger HonKit Build
        uses: peter-evans/repository-dispatch@v2
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
          event-type: honkit-build
          client-payload: '{"ref": "docs", "trigger": "weekly-report"}'
```

### 4단계: 브랜치 동기화

#### main 브랜치 커밋
```bash
git add .github/workflows/daily-report.yml \
        .github/workflows/weekly-report.yml \
        .github/workflows/honkit.yml

git commit -m "fix(workflows): trigger HonKit build after DevLog generation"
git push origin main
```

**커밋 해시**: `516f35dd0`

#### docs 브랜치 동기화
```bash
git checkout docs
git cherry-pick 516f35dd0
git push origin docs
```

**커밋 해시**: `d975414c3`

## 기술적 성과

### 워크플로우 자동화 완성

#### 이전 구조
```
daily-report 실행
  ↓
docs 브랜치 커밋
  ↓
❌ HonKit 실행 안됨 (push 이벤트 트리거 안됨)
  ↓
❌ gh-pages 업데이트 안됨
  ↓
❌ 404 에러
```

#### 개선된 구조
```
daily-report 실행
  ↓
docs 브랜치 커밋
  ↓
repository_dispatch 이벤트 발생
  ↓
✅ HonKit 자동 실행
  ↓
✅ gh-pages 자동 업데이트
  ↓
✅ GitHub Pages 정상 접근
```

### GitHub Actions 이벤트 시스템 활용

**학습한 개념**:
1. **repository_dispatch**: 워크플로우 간 이벤트 전달
2. **event-type**: 명확한 이벤트 타입 정의
3. **client-payload**: 추가 정보 전달 (트리거 소스 추적)
4. **peter-evans/repository-dispatch**: 안정적인 구현

**적용 범위**:
- daily-report → honkit 체이닝
- weekly-report → honkit 체이닝
- 향후 다른 워크플로우 체이닝에도 활용 가능

### 문서 자동화 시스템 완성도

**달성한 목표**:
- ✅ DevLog 자동 생성 (daily-report, weekly-report)
- ✅ SUMMARY.md 자동 업데이트 (generate_summary.py)
- ✅ HonKit 자동 빌드 (repository_dispatch)
- ✅ GitHub Pages 자동 배포 (gh-pages)
- ✅ Discord 자동 알림 (send_discord.py)

**결과**:
- **완전 자동화**: 개발자 수동 개입 불필요
- **일관성 보장**: 모든 문서가 자동으로 동기화
- **신뢰성 향상**: Discord 링크가 항상 작동

## 결론

### 해결 요약
- **문제**: GitHub Pages에서 최신 DevLog 404 에러
- **원인**: HonKit 워크플로우가 자동 실행되지 않음
- **해결**: repository_dispatch 이벤트 체이닝 구현
- **결과**: DevLog 생성부터 배포까지 완전 자동화

### 기술적 교훈
1. GitHub Actions는 Actions로 만든 커밋에 대해 push 이벤트를 트리거하지 않음
2. repository_dispatch는 워크플로우 체이닝에 효과적
3. 문서 자동화는 여러 워크플로우의 조화가 필요

### 향후 방향
- 알림 시스템 강화
- 빌드 성능 최적화
- 모니터링 체계 구축
