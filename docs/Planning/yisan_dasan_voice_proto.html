YiSan Dasan Voice Proto

분석 및 평가 보고서 (2025-09-30 ~ 2025-10-20)

이 보고서는 지정된 기간 동안 dopple, ju100, 은 화자의 개발 활동을 기반으로 각 프로젝트의 진행 상황, 기술적 성과 및 잠재력을 평가합니다.

1. Dasan (서버) 프로젝트

1.1. 프로토타입 기간 요약 보고서

Dasan 서버 프로젝트는 FastAPI를 기반으로 한 AI 에이전트 서버의 핵심 기능을 구축하고 배포 자동화까지 완료하는 빠른 개발 속도를 보였습니다.

초기에는 Docker와 기본 TTS/STT 모델(Bark, Whisper)을 연동하는 실험으로 시작하여, 빠르게 Google Cloud와 OpenAI의 GPT 모델을 통합하는 아키텍처로 발전했습니다. 특히 주목할 점은 STT/TTS 멀티 프로바이더 아키텍처를 도입하여 Google과 Naver Cloud Platform(NCP) 서비스를 동적으로 선택하고, 한 서비스에 장애가 발생했을 때 다른 서비스로 자동 전환되는 폴백(Fallback) 로직을 구현하여 서비스 안정성을 크게 향상시킨 것입니다.

또한, 단순 API 제공을 넘어 WebSocket을 통한 실시간 음성 스트리밍 수신, AI 에이전트의 페르소나(다산 정약용) 설정, 클라이언트의 공간 정보를 이해하는 컨텍스트 시스템 등 고도화된 기능을 구현했습니다. 개발 후반부에는 Render.com, Fly.io와 같은 클라우드 플랫폼에 배포를 자동화하고, 환경 변수 및 인증서 관리를 개선하는 등 운영 및 유지보수성을 고려한 성숙도 높은 개발이 진행되었습니다.

1.2. 일자별 수행 과업

  • 10월 16일: Fly.io 배포 설정 및 API 문서 업데이트.
  • 10월 15일: 음성 커맨드 CSV 로드 경로 수정, /ask 엔드포인트 기능 확장 (텍스트/공간정보 입력).
  • 10월 14일: STT/TTS 멀티 프로바이더(Google/NCP) 아키텍처 도입, API 명세 정리, 빈 메시지 방어 처리.
  • 10월 13일: Render.com 배포 자동화 및 인증 관리 개선, 신규 데이터 관련 정리.
  • 10월 12일: Google Cloud 및 OpenAI 기반 AI 에이전트 서버 초기 구현 (STT/LLM/TTS 파이프라인), 실시간 오디오 스트리밍 수신 기능 구현.
  • 10월 11일: Google TTS/GPT 연동, 구조 정리 및 백업.
  • 10월 10일: FishV2, Grok, Whisper 등 다양한 모델 연동 실험, Bark TTS 제거 및 CUDA 이슈 해결.
  • 10월 09일: Docker 설정, Bark TTS 연동 및 백업.
  • 10월 08일: Dasan 서버 초기 세팅.

1.3. 프로토타입 역량평가 및 프로젝트 평가

  • 기술적 역량: (최상)

    • FastAPI, WebSocket, 멀티 클라우드(Google/NCP), LLM(OpenAI) 등 최신 기술 스택을 능숙하게 조합하여 복잡한 AI 서비스를 단기간에 구축했습니다.
    • 멀티 프로바이더 및 폴백 아키텍처 설계는 높은 수준의 시스템 설계 능력을 보여주며, 이는 서비스 안정성과 확장성을 보장하는 핵심 요소입니다.
    • 배포 자동화(Render, Fly.io) 및 환경 구성(Docker) 경험은 단순 프로토타입을 넘어 실제 서비스 운영까지 고려하고 있음을 증명합니다.

  • 프로젝트 평가: (성공적)

    • 프로토타입의 목표(음성 기반 AI 에이전트 서버)를 초과 달성했습니다. 실시간 스트리밍, 컨텍스트 인지, 다중 서비스 연동 등 상용 서비스 수준의 기능들이 구현되었습니다.
    • 빠른 기술 탐색과 과감한 아키텍처 도입(예: Whisper -> Google STT, 단일 프로바이더 -> 멀티 프로바이더)을 통해 프로젝트의 품질을 지속적으로 개선했습니다.
    • 명확한 커밋 메시지와 API 문서 관리 등 협업과 유지보수를 고려하는 좋은 개발 습관이 엿보입니다.

2. YiSan (클라이언트) 프로젝트

2.1. 프로토타입 기간 요약 보고서

YiSan 클라이언트 프로젝트는 언리얼 엔진 C++을 중심으로 한 견고한 아키텍처 구축에 집중했습니다. 초기에는 프로젝트 설정, 코딩 컨벤션, 문서 자동화(Doxygen) 등 장기적인 유지보수를 위한 기반을 다지는 데 주력했습니다.

개발이 진행되면서 Dasan 서버와 통신하기 위한 네트워크 시스템(HTTP, WebSocket)을 구현하고, 이를 UI와 연동하는 작업이 핵심적으로 이루어졌습니다. 특히 이벤트 중심 아키텍처(BroadcastManager)를 도입하여 각 시스템(네트워크, UI, 플레이어, 음성) 간의 결합도를 낮추고 확장성을 확보한 점이 돋보입니다.

음성 시스템은 FAudioCapture를 활용한 녹음 기능부터 시작하여, 서버와 연동한 실시간 스트리밍, 수신된 TTS 데이터의 동적 재생(USoundWaveProcedural)에 이르기까지 점진적으로 발전했습니다. 또한, 플레이어의 위치와 시야를 파악하여 서버에 '공간 컨텍스트'를 제공하는 기능을 구현하여 AI 에이전트가 더 몰입감 있는 응답을 하도록 만들었습니다. UI는 C++ 중심으로 리팩토링하여 블루프린트 의존성을 줄이고 성능을 최적화했습니다.

2.2. 일자별 수행 과업

  • 10월 19일: UI 팝업(Mega/Small) C++ 기능 구현 및 리팩토링, 데이터 에셋 추가.
  • 10월 17일: 문서용 이미지 추가, 건물 상호작용(OnContact) 구조 정리.

  • 10월 15일: 음성 명령 시스템 및 퀘스트 시스템 구현, 건물 상호작용 로직 개선.
  • 10월 14일: 네트워크 상태 관리 리팩토링(카운트 기반), UI 상태 위젯 개선, GPT 공간 컨텍스트 시스템 구현.

  • 10월 10일: TObjectPtr 코딩 컨벤션 추가, 게이트 시스템 구현.

  • 09월 30일: 프로젝트 초기 설정.

1.3. 프로토타입 역량평가 및 프로젝트 평가

  • 기술적 역량: (최상)

    • 언리얼 엔진 C++에 대한 깊은 이해를 바탕으로 확장성 높은 아키텍처(이벤트 중심, 서브시스템, 액터 컴포넌트)를 설계하고 구현했습니다.
    • 네트워크(HTTP/WebSocket), 오디오(FAudioCapture, USoundWaveProcedural), 데이터 관리 등 언리얼 엔진의 핵심 기능을 능숙하게 활용합니다.
    • 블루프린트와 C++의 역할을 명확히 구분하고, 성능이 중요한 로직을 C++로 이전하는 등 최적화를 고려한 개발을 진행했습니다. Doxygen을 활용한 문서 자동화는 높은 수준의 코드 품질 관리 능력을 보여줍니다.

  • 프로젝트 평가: (성공적)

    • 서버와의 유기적인 연동을 통해 음성 기반 상호작용이라는 핵심 프로토타입 목표를 완벽하게 달성했습니다.
    • 견고한 기반 시스템(이벤트, 네트워크, 데이터 관리) 위에 음성, 퀘스트, UI 등 다양한 기능을 안정적으로 확장해 나가는 이상적인 개발 과정을 보여주었습니다.
    • 상세하고 체계적인 커밋 로그는 프로젝트의 히스토리를 명확하게 보여주며, 이는 팀의 지식 공유와 유지보수에 크게 기여할 자산입니다.

3. Voice (TTS/STT) 프로젝트

이 프로젝트는 SpeechGenerator와 SubtitleGenerator 저장소를 통합하여 평가합니다.

3.1. 프로토타입 기간 요약 보고서

Voice 프로젝트는 독립적인 TTS/STT 오픈소스 모델을 탐색하고 유틸리티를 개발하는 것을 목표로 진행되었습니다. SpeechGenerator에서는 모델 가이드 문서화 및 코드 정리가 이루어졌고, SubtitleGenerator에서는 음성 다운로드 및 자막 생성기능이 추가되었습니다.

이 프로젝트는 Dasan 및 YiSan 프로젝트와 비교했을 때 커밋 수가 적고, 주로 기존 오픈소스의 활용 및 간단한 유틸리티 개발에 초점을 맞춘 것으로 보입니다. 핵심적인 AI 기능 개발은 Dasan 프로젝트에서 외부 클라우드 서비스(Google, NCP)를 활용하는 방향으로 집중되면서, 이 프로젝트는 보조적인 역할이나 기술 탐색의 성격이 강했던 것으로 분석됩니다.

3.2. 일자별 수행 과업

  • 10월 18일: 제너레이터 코드 정리 (SubtitleGenerator).
  • 10월 17일: 서버 코드 추가 (SubtitleGenerator), 코드 정리 (SpeechGenerator).
  • 10월 16일: 가이드 문서 업데이트 및 셋업 (SpeechGenerator).
  • 10월 15일: 음성 다운로드/자막 생성기 추가 (SubtitleGenerator).

3.3. 프로토타입 역량평가 및 프로젝트 평가

  • 기술적 역량: (중)

    • Python 기반의 오픈소스 모델을 활용하고 간단한 스크립트를 작성하는 기본적인 역량을 보여주었습니다.
    • 하지만 기간 내 활동이 적어 이 프로젝트만으로는 심층적인 기술 역량을 평가하기에 제한적입니다. Dasan 프로젝트에서 보여준 Python 및 AI 서비스 개발 역량을 고려할 때, 이 프로젝트는 우선순위가 높지 않았을 가능성이 큽니다.

  • 프로젝트 평가: (탐색 단계)

    • 프로젝트의 목표가 명확한 결과물 도출보다는 기술 탐색 및 보조 유틸리티 개발에 가까워 보입니다.
    • 핵심 기능이 Dasan 서버 프로젝트로 통합되면서, 이 프로젝트의 역할은 자연스럽게 축소된 것으로 판단됩니다. 독립적인 프로젝트로서의 성과보다는, 핵심 프로젝트(Dasan)의 기술적 의사결정 과정에서 이루어진 사전 조사 및 실험의 일부로 보는 것이 타당합니다.
