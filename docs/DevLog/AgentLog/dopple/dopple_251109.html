GitHub Pages DevLog 404 문제 해결 및 자동화 완성

사용자 피드백을 통해 발견된 GitHub Pages에서 최신 DevLog가 표시되지 않는 문제를 근본적으로 해결했습니다.

문제 분석:

  1. daily-report → docs 브랜치에 파일 생성
  2. Discord 링크 → GitHub Pages (gh-pages 브랜치)
  3. gh-pages에는 docs 브랜치 내용이 자동 반영되지 않음 → 404 에러

근본 원인:

  • HonKit 워크플로우가 docs 브랜치의 push를 트리거하도록 설정되어 있었으나 실제로 실행되지 않음
  • docs 브랜치에 커밋 후 HonKit 빌드가 자동으로 실행되지 않아 gh-pages가 업데이트되지 않음

해결 방법: repository_dispatch 이벤트를 사용한 워크플로우 체이닝 구현

1. honkit.yml 수정

  • repository_dispatch 트리거 추가
  • types: [honkit-build] 이벤트 수신 설정
  • daily/weekly report 완료 후 자동 실행되도록 구성

2. daily-report.yml 수정

  • HonKit 빌드 트리거 단계 추가
  • peter-evans/repository-dispatch@v2 액션 사용
  • 파일 생성 후 자동으로 HonKit 빌드 트리거

3. weekly-report.yml 수정

  • daily-report와 동일한 트리거 메커니즘 추가
  • 주간 리포트 생성 후 자동 HonKit 빌드

변경 파일

수정된 파일:

  • .github/workflows/honkit.yml:

    • repository_dispatch 트리거 추가 (17-19줄)
    • daily/weekly report 완료 이벤트 수신

  • .github/workflows/daily-report.yml:

    • "Trigger HonKit Build" 단계 추가 (170-175줄)
    • repository-dispatch 액션으로 HonKit 빌드 트리거

  • .github/workflows/weekly-report.yml:

    • "Trigger HonKit Build" 단계 추가 (169-174줄)
    • repository-dispatch 액션으로 HonKit 빌드 트리거
